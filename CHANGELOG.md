# Changelog

## 0.6.1 — 2026-11-18

本版在设置页加了更新和反馈问题两个按钮，并修好了 [#84](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/84)：DSH 带着 Windows 兼容性设置运行时，DSH 浏览器选 Edge 就打不开。/ This release adds Update and Report a problem buttons to the settings page and fixes [#84](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/84): with DSH running under a Windows compatibility setting, the DSH browser did not open when it was Edge.

- 设置页能直接更新插件。DSH 每次启动时自动检查新版本；有新版本时，标题右侧 GitHub 左边出现“更新”，左侧“电脑操控”旁出现小红点，点一下就由 DSH 自带的插件市场安装，页面显示进度，装完说明怎么生效（DSH Desktop 上是从托盘退出再打开）。没有新版本时那里什么都不显示。插件市场默认等新版本发布满一天后才提供；没有插件市场，或者插件是从本地文件装的时，“更新”打开升级说明。/ The plugin can be updated from the settings page. DSH checks for a new version at every start; when one exists, an Update button appears left of the GitHub link at the top right and a small red dot shows next to Computer Use on the left. One click installs it through DSH's bundled plugin market, the page shows progress, and afterwards it says how to finish (on DSH Desktop: quit from the tray and reopen). With no new version, nothing shows there. The plugin market offers a new version one day after its release by default; without the market, or for a plugin installed from a local file, Update opens the upgrade steps.
- 遇到问题可以一键反馈：设置页标题右侧点“反馈问题”，插件把诊断信息存成下载文件夹里的 txt 文件，里面有环境、设置、插件自检、最近 30 次电脑操控调用和 DSH 日志里相关的行；设置页提示已保存，同时打开下载文件夹和 GitHub 新建问题页面，把文件拖进去即可。用户目录、用户名和计算机名会替换，输入的文字只保留长度，不带截图。/ Problems can be reported in one click: Report a problem at the top right of the settings page saves the diagnostics as a text file in your Downloads folder, with the environment, settings, the plugin's self-test, the last 30 computer-use calls and the related DSH log lines; the page says so, and the Downloads folder and GitHub's new-issue page open, ready for the file. User folders, the user name and the computer name are replaced, typed text is kept as its length only, and there are no screenshots.
- 设置页顺序改为工具在最上面，然后是网页与浏览器；标题只写“电脑操控”。/ The settings page now starts with Tools, then Web and browser, and the title reads just the name.
- DSH 浏览器用 Edge 时能正常打开了。DSH 带着 Windows 兼容性设置运行时，进程环境里有 `__COMPAT_LAYER`，这个变量会传给 DSH 启动的每个程序。Edge 发现自己带着它，会关掉自己再重开一次：第一个进程大约 50 毫秒就退出，重开的进程接不上插件和浏览器之间的管道。所以在 0.6.0 里，这种情况下 DSH 浏览器每次都打不开：临时配置报 `BROWSER_DISCONNECTED`，开着“保留网站登录”报 `exited during startup (0)`。0.5.7 走调试端口，开着“保留网站登录”时，重开的 Edge 下一次调用还能接上，所以 #84 看到的只是第一次失败。现在 DSH 浏览器启动时不带这个变量，并加上 `--edge-skip-compat-layer-relaunch`（Playwright 也用这个开关），Edge 不再重开。Chrome 不受影响。/ The DSH browser opens again with Edge. With DSH running under a Windows compatibility setting, its environment carries `__COMPAT_LAYER`, which passes on to every program DSH starts. Edge that finds it closes itself and starts again: the first process exits after about 50 ms, and the new one cannot take over the pipe between the plugin and the browser. In 0.6.0 the DSH browser therefore failed every time in this case, with `BROWSER_DISCONNECTED` on a temporary profile and `exited during startup (0)` with Keep website sign-ins on. 0.5.7 used a debugging port, so with Keep website sign-ins on the next call could still reach the restarted Edge, which is why #84 saw only the first call fail. The DSH browser now starts without the variable and with `--edge-skip-compat-layer-relaunch`, the switch Playwright passes too, so Edge no longer restarts. Chrome was not affected.
- 测试：`browser-signin` 让保留登录和临时配置两条启动路径都在带 `__COMPAT_LAYER` 的环境下打开真实的 Edge，0.6.0 在第一处就失败；`client-settings-contract` 用模拟的插件市场把更新按钮的各种情况走了一遍：启动时检查、打开设置页时重查过时的结果、进度、市场正忙、版本太新时“仍要更新”、装上的版本不对、要重启或刷新、本地安装、没有插件市场时改查 npm、离线，以及“反馈问题”的成功和失败；新增的 `diagnostics` 套件检查脱敏、调用记录、诊断文件、打开的两个窗口和接口的同源检查，套件数从 87 变成 88。/ Tests: `browser-signin` now opens real Edge under `__COMPAT_LAYER` on both the kept-profile and the temporary-profile path, and 0.6.0 fails at the first; `client-settings-contract` runs the update button through a simulated plugin market: the startup check, a repeat check when the page opens on a stale result, progress, a busy market, Update anyway for a too-fresh release, a wrong installed version, restart or reload, a local install, npm without a market, offline, and Report a problem succeeding and failing; the new `diagnostics` suite checks redaction, the call log, the diagnostics file, the two windows it opens and the route's same-origin check, taking the suite count from 87 to 88.

## 0.6.0 — 2026-11-15

因为更强的模型 Fable 5.2 和 4 Carbon 发布，我决定对插件代码做一次彻底的优化和重构，以提升使用体验。这次由 Fable 5.2、6.1 Sol、4 Carbon 和 Opus 5.5 四个模型分工完成，各自做了什么见本节末尾的“分工”。发布前我做了全面的人工使用评测，尽可能保证实际使用不出问题；当然，问题没法彻底避免，遇到新问题请提 issue。/ With the release of the stronger Fable 5.2 and 4 Carbon models, I decided to thoroughly optimize and refactor the plugin's code for a better experience. Four models shared the work, Fable 5.2, 6.1 Sol, 4 Carbon and Opus 5.5; see "Who did what" at the end of this entry. Before the release I evaluated it thoroughly by hand in real use to keep everyday use free of problems as far as possible; problems can never be ruled out entirely, so please open an issue if you hit a new one.

本版合并的 PR：[#81](https://github.com/Yu-tao-Li/dsh-computer-use-win/pull/81)（俄文词典，补完 [#74](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/74) 的俄文部分）。本版还修好了 [#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82) 报告的几个问题。发布时所有 issue 都已关闭。/ Merged in this release: [#81](https://github.com/Yu-tao-Li/dsh-computer-use-win/pull/81) (the Russian dictionary, completing the Russian part of [#74](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/74)). This release also fixes the problems reported in [#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82). Every issue is closed at release time.

这次是怎么做的：和 0.5.7 相比，改动涉及 153 个文件，新增约 9500 行、删掉约 1600 行代码。先把 0.5.7 的代码从头审了一遍，列出 60 多个问题，最严重的 10 个在这一版全部修好，其余的大部分也已修复。再重搭骨架、升级测试（见下面的“结构”和“开发”），新加的 11 个模块各管一件事。最后由几个模型交叉复核代码，并把候选版装进 DSH Desktop，按一份 45 项的清单在真实的程序和网页上逐项试用，发现的问题修好以后再复测。/ How it was done: compared with 0.5.7, 153 files changed, with about 9,500 lines added and 1,600 removed. The 0.5.7 code was first reviewed from end to end, which turned up more than 60 problems; the 10 most serious are all fixed in this release, and most of the rest too. Then the structure was rebuilt and the tests were upgraded (see Structure and Development below), with eleven new modules that each do one job. Finally the models cross-checked each other's code, and the candidate was installed in DSH Desktop and tried item by item against a 45-item checklist on real apps and web pages; whatever turned up was fixed and checked again.

- 敏感操作改由 DSH 先问你：带参数启动程序、通过快捷方式（.lnk）启动程序、在网页里打开本机文件（`file://`）、把本机文件上传到网页、连接你自己已打开的浏览器、第一次操作你自己浏览器里的标签页，DSH 都会先弹出确认，同意后才执行，拒绝或取消就不执行。同意只对这一次调用、这组参数有效，两分钟内用一次；这份许可由插件签名，模型看不到，也伪造不了。agent 不能对 DSH 自己的窗口发键盘鼠标，所以没法替你点“同意”。在 DSH 的“完全权限”方案下（不弹审批，DSH 会自动拒绝一切审批请求），这几类操作直接执行、不询问，因为这时 agent 本来就能不经确认运行任何命令；其他方案照常先问你。单独运行的 MCP 服务（比如接在其他 MCP 客户端里）没有确认框，这几类操作默认拒绝，可以用 `WCU_ALLOWED_FILE_ROOTS`、`WCU_ALLOWED_UPLOAD_ROOTS`、`WCU_ALLOWED_LAUNCH_PROGRAMS`、`WCU_ALLOW_LAUNCH_ARGUMENTS` 放开，见[安全说明](docs/wiki/safety.md)。已在 DSH 0.1.0-rc.6、0.1.0-rc.7、0.2.1-rc.2、0.2.2-rc.1 的真实宿主上验证。/ DSH now asks before sensitive operations: launching a program with arguments or through a shortcut, opening a local file in a page, uploading a local file to a page, connecting to your own browser, and the first action on one of your own tabs. A refusal or cancel runs nothing. An approval is signed by the plugin, bound to that one call and its arguments, valid for two minutes and usable once; the model never sees it and cannot forge it. The agent cannot send input to DSH's own windows. Under DSH's Full access preset, where DSH rejects every approval request, these calls run unasked, since that preset already lets the agent run any command; other presets ask. Standalone MCP refuses these calls unless environment variables allow them.
- 浏览器通道更安全：不打开云服务器的元数据地址（如 169.254.169.254）和 DSH 自己在本机的端口，网页里的子请求和跳转同样拦下；不接受网络路径的文件，打字和按键里不接受控制字符和私用区字符。网页文字和对话框内容在结果里用每次随机生成的边界包起来，并标明是不可信的数据，提醒模型不要把网页上的话当成指令。网页密码框里的内容不再交给模型，只返回它的长度。/ The browser lane refuses cloud metadata addresses and DSH's own local ports, including subrequests and redirects, network file paths, and control or private-use characters in typed text and keys. Page text and dialog messages come back inside a random per-result boundary marked as untrusted data. The content of a password field is no longer passed to the model, only its length.
- DSH 浏览器不再开本机调试端口：Chrome 和 Edge 改用启动时继承的管道通信（`--remote-debugging-pipe`）；打开“保留网站登录状态”时，几个 DSH 通过名字随机的命名管道共用同一个浏览器，本机其他程序找不到调试端口来连它。/ The DSH browser opens no local debugging port: Chrome and Edge talk over an inherited pipe, and with kept sign-ins several DSH servers share the browser through a randomly named pipe.
- 浏览器通道能读、能操作 iframe 里的内容，包括跨域和嵌套的 iframe；元素 ID 记着自己所在的 frame 和文档，页面跳转后失效。传 `browserTab` 时坐标按页面截图的 CSS 像素算，可以点 canvas，不动桌面鼠标。看得见的 DSH 浏览器空闲 2 小时才关（无头模式仍是 10 分钟），翻页、标题变化和对话框都算活动。电脑操控读 Firefox 网页更可靠：先唤醒 Firefox 的无障碍树，并去掉屏幕外的叶子节点，默认深度就能读到网页内容。/ The browser lane reads and operates iframes, including cross-origin and nested ones; with `browserTab`, coordinates are CSS pixels of the page screenshot, so canvases can be clicked. A visible DSH browser closes after two idle hours (headless: 10 minutes). Computer Use reads Firefox pages more reliably: it wakes Firefox's accessibility tree first and prunes offscreen leaves, so default depths reach the page.
- 键盘鼠标更稳、更不容易点错 / Input:
  - 停止键单独用一个线程监听，不再和浮窗绘制挤在同一个线程里，浮窗绘制拖不住 Esc。/ The stop key listens on a thread of its own instead of sharing one with the overlay's drawing, so drawing cannot hold up Esc.
  - 插件自己发出的键盘鼠标带一个每次启动随机生成的标记，Esc 停止只忽略带这个标记的输入，所以通过远程控制软件按下的 Esc 现在也能停止操作。/ The plugin's own input carries a random per-run marker, and only that input is ignored by the stop key, so Esc sent through a remote-control tool now stops the series.
  - 同一时间只有一个插件进程能发键盘鼠标，另一个直接得到“忙碌”，不会排队后补发；在一个 DSH 里按 Esc，同一用户下正在操作的其他 DSH 也一起停下。/ One process sends input at a time and others get “busy” instead of a delayed replay; Esc in one DSH stops the others of the same user.
  - 点元素之前先确认它看得见、能用，而且那个位置上确实是它，被别的东西挡住就不点；同一程序的其他窗口（比如另一个资源管理器窗口）不再当作目标窗口。/ Element clicks check that the element is visible, enabled and really under the point; other windows of the same program no longer count as the target.
  - 按窗口标题找窗口时，先找完全相同的，再找开头相同的，最后找包含的；对上多个就报错并列出候选窗口的句柄，不再随便挑第一个。只给进程号时，只在有标题、看得见的窗口里挑，程序自带的隐藏窗口（输入法、DDE 等）不算。/ A window title matches exactly, then by prefix, then as a substring, and several matches are refused with the candidates' handles; a process id alone picks among titled visible windows, ignoring a program's hidden helper windows.
  - 坐标点击不再悄悄按“窗口挪动了多少”去改位置；需要按窗口移动修正时，把观察结果里的 `observationToken` 一起传回。/ Coordinate clicks are corrected for window movement only when the observation's `observationToken` is passed back.
  - 后台的 `set_value`、`invoke`、元素点击和元素滚动也算 DSH 在这个窗口里操作过，接下来不带窗口目标的按键和输入会发到这个窗口。以前在地址栏 `set_value` 之后直接按 Enter，Enter 会落到当时在前台的窗口，网页没跳转，结果却显示已发送（[#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82)）。/ Background `set_value`, `invoke`, element clicks and element scrolls now count as DSH working in that window, so a following key or text without a window target goes there. Before, Enter after `set_value` on an address bar went to whichever window was in front, and the page never navigated while the result said sent ([#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82)).
  - `keypress` 和 `type_text` 的结果新增 `deliveredTo`，写明输入实际到了哪个窗口（句柄、进程、标题）、这个窗口是怎么选的，以及窗口在前台时有键盘焦点的控件（比如“地址和搜索栏”）。没给窗口目标、这一轮又还没操作过任何窗口时，输入会落到前台窗口，结果标为 `unconfirmed`，不再报 `sent`。/ `keypress` and `type_text` results include `deliveredTo`: the window that got the input (handle, process, title), how it was chosen, and, for a window in front, the control with the keyboard focus, such as the address bar. Input without a window target before DSH has worked in any window this turn reaches the window in front and is reported `unconfirmed` instead of `sent`.
  - `list_windows` 默认也列出最小化的窗口，标 `minimized: true`，不带 Windows 停放它们的 -32000 坐标；以前它们被悄悄漏掉，看起来像程序已经关了。窗口数超过 `maxWindows` 时结果标 `truncated`；`includeInvisible` 的说明写明它加的是完全隐藏的窗口（[#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82)）。/ `list_windows` lists minimized windows by default, marked `minimized: true` and without the -32000 position Windows parks them at; they used to be left out silently, which looked like the app had closed. A list cut by `maxWindows` says `truncated`, and `includeInvisible` is described as adding fully hidden windows ([#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82)).
  - `activate_window` 恢复最小化的窗口时，会等它真的恢复了再往下做；Windows 不理会恢复命令时，再用窗口菜单的“还原”试一次；还是没恢复，就报 `activated: false` 并说明原因，不再报成功。结果里的 `window` 改为调用之后的窗口，并标 `restored: true`；以前它是调用之前读的，刚恢复的窗口还显示最小化时的 -32000 坐标，看起来像没恢复（[#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82)）。/ `activate_window` waits until a minimized window is actually restored and, when Windows ignores the request, tries the Restore command of the window menu; a window left minimized is reported as `activated: false` with the reason instead of success. `window` in the result now describes the window after the call, with `restored: true`; it used to be read before the call, so a window just restored still showed its minimized -32000 position and looked untouched ([#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82)).
  - `keypress` 新增 `thenKeys`：一次调用按顺序按下几组键，整个过程只借用一次前台，中间不把前台还回去，所以 Excel 功能区的 Alt、H、O、W 这类连续按键不会被打断；每组键之前照常检查 Esc 和前台，出错就停下，已经按下的键不会重发。给模型的说明里也补上了 Excel 排版的做法：用 Ctrl+G 选定区域，列宽填数字或自动调整（数值等对话框出现后再输入），长文字设好宽度后打开自动换行，再自动调整行高，最后检查保存的结果。/ `keypress` takes `thenKeys`: several chords in order within one foreground lease, so Excel Ribbon sequences such as Alt, H, O, W are not interrupted; each chord still checks Esc and the foreground, and a failure stops without resending keys. The model instructions also describe Excel layout: select with Ctrl+G, numeric or AutoFit column widths (values typed once the dialog shows), Wrap Text for long text, AutoFit row height, then check the saved result.
  - `launch_app` 拒绝网络路径；快捷方式按它实际指向的程序判断；python、node 等脚本解释器带参数时同样拒绝。/ `launch_app` refuses network paths, judges a shortcut by the program it starts, and refuses arguments for more script interpreters.
- 剪贴板：粘贴的文字标记为不进剪贴板历史、不上传云剪贴板、剪贴板监控程序不处理；目标程序读走文字以后才恢复你原来的剪贴板，目标一直没来读，就把这次的文字留在剪贴板上并在结果里注明，免得慢一点的程序粘进你原来的内容。记事本、写字板这类原生输入框改为直接粘贴，粘贴完成就恢复；UU 远程这类会先读走剪贴板的软件开着时也能恢复（以前会一直等不到确认）。/ Pasted text is marked to stay out of clipboard history, cloud clipboard and monitors. Your clipboard is restored only after the target has read the text; otherwise the text stays and the result says so. Native edit boxes such as Notepad and WordPad paste directly and restore as soon as the paste completes, also while a tool that reads the clipboard first, such as UU Remote, is running.
- 截图：窗口截图会带上这个窗口自己弹出的对话框和菜单，比如 Excel 的“列宽”对话框，模型不会再以为命令没生效而重复操作；插件自己截图和做文字识别时，屏幕提示和浮窗暂时不进截图；删掉了从来没能编译成功的 WGC 截图代码（实际一直用 PrintWindow 和屏幕区域截图）。最小化的窗口截图只能拍到标题栏那一小条，结果现在标 `minimized: true` 并提示先恢复；对最小化的窗口做文字识别会直接报错并说明原因（[#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82)）。/ Window screenshots include the window's own dialogs and menus, such as Excel's Column Width box, so the model no longer repeats a command that did work. The plugin's own screenshots and OCR leave out its indicators and overlay; the WGC capture code, which never compiled, is removed. A screenshot of a minimized window gets only its title strip, so the result now says `minimized: true` and to restore the window first; OCR of a minimized window fails with that reason ([#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82)).
- 文字识别：`ocr` 带 `query` 时只返回命中的那几行（带每个词的坐标）和总行数 `lineCount`，不再附上全部文字和所有词的坐标；没命中时返回每一行的文字和位置，方便换个说法再找。一个 1500×900、满屏文字的窗口，结果从约 52,000 字符降到约 2,400 字符（命中）或 5,700 字符（没命中），`find` 的 OCR 兜底也一样（[#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82)）。/ OCR: `ocr` with `query` returns only the matching lines (with their word boxes) and `lineCount` instead of the whole text and every word box; without a match it returns every line's text and box to reformulate from. For a 1500 × 900 window full of text the result went from about 52,000 characters to about 2,400 (hit) or 5,700 (miss), and `find`'s OCR fallback shrinks the same way ([#82](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/82)).

- 修复 OCR 在部分电脑上每次都报“指定路径 C:\Users\XXX~1 下的对象不存在”，`find` 的 OCR 兜底也一样（[#78](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/78)）。原因在 Windows PowerShell 5.1 的文件系统提供程序：TEMP 是 8.3 短路径、而短名比原名还长时（用户名很短又带空格，如 `Li Hua` 的短名是 `LIHUA~1`），删除临时文件的命令会报这句错。OCR 每次编译识别组件都要删临时文件，所以每次都失败，还在 TEMP 里留下一对半成品文件。现在临时文件全部用 .NET 处理，编译前清掉一小时前的半成品。顺带修正截图清理拿本地时间和 UTC 比较，在西半球的时区会删掉刚截的图。/ OCR failed on every call with “An object at the specified path C:\Users\XXX~1 does not exist” when TEMP is an 8.3 path whose short name is longer than the real one (a short user name with a space): Windows PowerShell 5.1 rejects such paths when deleting files, and every OCR compile deleted its temporary files. - 修复 DSH 跑在 WSL 里时，所有发送输入的工具都报“-File 形式参数实际参数……不存在”，之后连读屏也一起暂停（[#79](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/79)）。PowerShell 是 Windows 程序，按自己的当前盘解析 Linux 路径：从 `/mnt/c/...` 启动 DSH 时，脚本路径被解析成 `C:\home\...`。现在脚本以 Windows 路径（`wslpath -w`）交给 PowerShell，工作目录设为脚本所在目录；Esc 停止用的变量经 `WSLENV` 传给 Windows 进程；接管助手报告自己的 Windows 进程号；截图路径换成 WSL 里能直接读的 `/mnt/...`。接管助手起不来时只拒绝真正的键盘鼠标输入，读屏、后台操作和浏览器通道照常，也不再每秒反复启动 PowerShell。/ Under WSL every input tool failed with “-File … does not exist” and then paused reading as well: PowerShell resolved the Linux script path against its own current drive. Scripts now get their Windows path and directory, the stop event reaches Windows through `WSLENV`, the takeover helper reports its Windows process id, and screenshot paths come back as `/mnt/...`. ### Electron 和 Chromium 的网页控件 / Chromium page accessibility (#50)

- Chromium 把网页放在六层以上没有名字的布局 Pane（NonClientView、ClientView、View 等）下面，默认深度（snapshot 5、tree 6、find 8）到不了网页，即使强制打开无障碍也一样。在窗口范围的树里，这些 Pane 现在不计入 `maxDepth`；返回的 `depth` 仍是实际层级，额外层数最多 16 层。桌面范围的树不变，仍是所有窗口的概览。 / Chromium nests a page under six or more unnamed layout panes (NonClientView, ClientView, View and so on), so the default depths (snapshot 5, tree 6, find 8) never reached it, even with forced accessibility. - **Made `viewMode`/`includeOffscreen` behaviour consistent and documented** ([#4](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/4)): the two parameters apply to scope resolution and tree walking; `uia:rt:*` element ids are looked up directly by RuntimeId and bypass view filtering by design. `viewMode` is now validated on every path (an illegal value used to be silently swallowed on the `uia:rt:*` path while the legacy path threw), and the schema descriptions plus `docs/wiki/mcp-tools.md` document the semantics.
- **`activate` now works or is honestly documented on every path that declares it** ([#5](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/5)): `activate` was only read by drag/type_text/keypress and element-target resolution. Now the x/y coordinate paths of `click`/`double_click`/`move`/`scroll` activate the target window first (coordinate input hits whatever is physically under the point — with the target occluded, input silently landed on the overlapping window); `ocr` brings the window forward before capturing when `activate: true` (an occluded window captured the occluder's pixels; if the foreground lock refuses activation the result carries a `warning` instead of failing); `move_window` honours `activate: true` (the hardcoded `SWP_NOACTIVATE` is now conditional, and the switch is enforced via the `Set-WindowForeground` helper — `SetWindowPos`'s implicit activation is silently refused by the Windows foreground lock; the result gains an `activated` field plus a `warning` when refused, default unchanged); `element_info`'s FromPoint path activates too. `close_window` (WM_CLOSE works in the background) and `activate_window` (the tool is the activation) now document their semantics. Thanks to [@TomJerry234](https://github.com/TomJerry234) for the automated audit.
- Fixed `mcp/server.mjs` reporting a hardcoded `SERVER_VERSION` that drifted from `package.json`: the version is now read from `package.json`.

## 0.2.1 — 2026-09-26

- 修复窗口激活无条件调用 `SW_RESTORE` 的问题：对最大化/贴靠窗口执行带 `activate: true` 的工具时会取消其最大化并重置位置大小（含用户自己的宿主窗口，并连带导致坐标点击偏移）。现在仅当窗口确实最小化（`IsIconic`）时才还原，其余情况不动窗口状态。感谢 [@snmtg1008](https://github.com/snmtg1008) 在 [#2](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/2) 中定位并给出修法。
- Fixed window activation unconditionally calling `SW_RESTORE`: any tool run with `activate: true` un-maximized maximized/snapped windows and reset their position and size (including the user's own host window, and cascading into misaligned coordinate clicks). `SW_RESTORE` is now issued only when the window is actually minimized (`IsIconic`); otherwise the window state is left untouched. Thanks to [@snmtg1008](https://github.com/snmtg1008) for diagnosing the issue and proposing the fix in [#2](https://github.com/Yu-tao-Li/dsh-computer-use-win/issues/2).
