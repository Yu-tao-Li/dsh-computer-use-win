# Architecture

DSH ToolRuntime calls the official MCP bridge, which starts mcp/server.mjs in Node mode (including Electron via ELECTRON_RUN_AS_NODE). The Node server validates arguments against the same schemas it advertises. One persistent PowerShell backend serializes desktop requests; queued request time is not counted as execution time.

## Observation

UIA trees use cached properties, a node cap, a depth cap and a traversal time budget. One synchronous provider call can still block. The server watchdog allows the budget plus 10 seconds, retires a stuck worker, and may obtain a native screenshot from a replacement. The response preserves explicit failure; an image is not a successful accessibility tree.

Native window enumeration, screenshot, default OCR, coordinate targeting and window management do not resolve UIA elements. Fully on-screen, unobstructed foreground windows use a screen crop, with foreground HWND, Z order and geometry checked before and after capture. Other windows use PrintWindow, Windows.Graphics.Capture and a flagged screen-region fallback. These capture APIs have their own watchdog; UIA independence is not a guarantee that every capture API is interruptible.

Empty sparse/incomplete find results can attach OCR. OCR candidates have source:ocr, recognized text and screen-space bounds. Literal OCR text does not prove a control role. Explicit resolveControl requests a UIA hit-test, whose result may be a whole document. Screenshot image pixels map to screen = bounds origin + image / imageScale.

## Actions and evidence

Each action uses the least intrusive way that works (less takeover, issue #45). Element actions run in the background: BM_CLICK for Win32 buttons, EM_REPLACESEL for Win32 edits, WM_VSCROLL/WM_HSCROLL for controls with their own scroll bars, else the UIA pattern under a guard that gives back the foreground and the pointer a provider took on its own (managed Win32 proxies and Chromium activate their window for most pattern calls), unless a menu, list or dialog the call opened is showing. Real input borrows the foreground: Start-Input notes the window in front and the pointer and brings the target forward (joining the input of the thread in front first, the Alt-key method second); Assert-PointOnTarget refuses a click whose point shows another process's window; Assert-InFront checks once more right before keys go out; Complete-Input, in finally, waits for the target to handle the input (two WM_NULL), then puts the pointer back if it is still where DSH left it and returns the foreground, except with activate:true, while the target's thread is in menu mode or shows a popup that was not there before, or when the user switched windows. The window input went to is remembered with the host's series key (_wcuSeries), so input and observations without a window target keep to it after the foreground went back to the user. type_text preserves the current focus by default, so it can follow an OCR/visual click without refocusing another control. focusMode:main explicitly requests heuristic main-control focus.

The server classifies calls with isQuietCall (mcp/browser.mjs), shared with the host's activity tracking: reads, list_windows, wait, background dispatch, browser-lane calls and element actions that start in the background take a quiet lease (no takeover helper, so no indicator and no global Esc), and only a call that uses the real pointer or keyboard turns on the series indicator. Element actions, scroll on an element and type_text in auto mode first run with _wcuQuiet; when they would need real input the backend throws WCU_NEEDS_INPUT before sending any, and the server runs them again with a normal lease.

RuntimeId references are cached from observations with HWND/PID ownership and a five-minute lifetime. Unseen/stale ids require re-observation; the backend does not globally search the desktop for them. Legacy tree paths remain view-dependent.

Actions report verification:sent. A UIA pattern call or native input acceptance does not prove the user's objective. wait_for supports native window presence, bounded UIA element queries, and literal OCR text. A satisfied observable condition reports verification:observed. Truncated UIA absence and occluded OCR remain inconclusive.

Input cancellation allows press/release cleanup before worker retirement. Timed-out input is never replayed. Clipboard data is read before replacement and restored in finally; pasted text carries ExcludeClipboardContentFromMonitorProcessing, CanIncludeInClipboardHistory=0 and CanUploadToCloudClipboard=0, so it stays out of clipboard history and the cloud clipboard. Drag release is also attempted in finally.

## Browser lane

mcp/browser.mjs speaks the Chrome DevTools Protocol from the Node server over WebSocket, beside the PowerShell backend rather than through it. It uses its own small WebSocket client without compression: Node's built-in client negotiates permessage-deflate and drops the connection on any message over 4 MiB decompressed, which the accessibility tree of a long page exceeds. A call routes there when it carries browserTab or a page element id. Each tab gets one flattened session; pages are read with Accessibility.getFullAXTree and flattened into an outline; input uses Input.dispatchMouseEvent / dispatchKeyEvent / insertText inside the page after a hit test. Element ids are numbers the server run hands out and maps to a DOM node of one document; tab ids carry a salt of the run, so ids from an earlier run never reach a tab. Actions in a tab run one at a time. Browser-lane calls take a quiet takeover lease: a stopped series still refuses them and settings reconnects wait for them, but they start no takeover helper, so they show no screen indicator and arm no global Esc; DSH's stop button cancels them. The agent browser is a visible-by-default child process (headless is opt-in) running the browser chosen in settings (by default the Windows default browser, read from UserChoiceLatest\ProgId, else UserChoice), whose tabs run in an isolated browser context of a throwaway profile; with sign-ins kept, it runs on a kept profile instead and its tabs use that profile's own context, so the sites the user signed in to there stay signed in. The user's own browser is never connected; see the browser lane section of mcp-tools.md. All usable presets receive browser-first routing instructions at MCP initialization; disabled tools are not advertised as callable. The visible agent browser marks its work without covering the page, as Codex's Browser Use does: a DSH-blue window frame (an autogenerated theme), a pointer badge as the icon of the tab DSH works in, and a small pointer at the point it acts on, drawn in a closed shadow root of an isolated world that lets pointer events through and is hidden for screenshots. Visible targets are created with background:true; automatic activation remains limited to headless tabs. A tab that is not painting (background or minimized) is captured by repeating the capture request until Chrome answers, never by activating its window.

## Vision

No visual model is bundled. A vision-capable caller or optional external parser such as OmniParser can consume screenshot content and return coordinates to the same guarded input tools.
