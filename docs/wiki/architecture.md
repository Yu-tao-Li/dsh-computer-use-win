# Architecture

DSH ToolRuntime calls the official MCP bridge, which starts mcp/server.mjs in Node mode (including Electron via ELECTRON_RUN_AS_NODE). The Node server validates arguments against the same schemas it advertises. One persistent PowerShell backend serializes desktop requests; queued request time is not counted as execution time.

## Observation

UIA trees use cached properties, a node cap, a depth cap and a traversal time budget. One synchronous provider call can still block. The server watchdog allows the budget plus 10 seconds, retires a stuck worker, and may obtain a native screenshot from a replacement. The response preserves explicit failure; an image is not a successful accessibility tree.

Native window enumeration, screenshot, default OCR, coordinate targeting and window management do not resolve UIA elements. Fully on-screen windows in the foreground, including through their owned dialogs or menus, use a screen crop; owned popups remain visible in it. Foreground ownership, Z order and geometry are checked before and after capture, and unrelated overlaps still prevent an unobstructed crop. Other windows use PrintWindow and a flagged screen-region fallback. WGC is not implemented in this candidate. These capture APIs have their own watchdog; UIA independence is not a guarantee that every capture API is interruptible.

Empty sparse/incomplete find results can attach OCR. OCR candidates have source:ocr, recognized text and screen-space bounds. Literal OCR text does not prove a control role. Explicit resolveControl requests a UIA hit-test, whose result may be a whole document. Screenshot image pixels map to screen = bounds origin + image / imageScale.

## Actions and evidence

Each action uses the least intrusive way that works (less takeover, issue #45). Element actions run in the background: BM_CLICK for Win32 buttons, EM_REPLACESEL for Win32 edits, WM_VSCROLL/WM_HSCROLL for controls with their own scroll bars, else the UIA pattern under a guard that gives back the foreground and the pointer a provider took on its own (managed Win32 proxies and Chromium activate their window for most pattern calls), unless a menu, list or dialog the call opened is showing. Real input borrows the foreground: Start-Input notes the window in front and the pointer and brings the target forward (joining the input of the thread in front first, the Alt-key method second); Assert-PointOnTarget checks the window at the input point; Assert-InFront checks once more right before keys go out; Complete-Input, in finally, waits for the target to handle the input (two WM_NULL), then puts the pointer back if it is still where DSH left it and returns the foreground, except with activate:true, while the target's thread is in menu mode or shows a popup that was not there before, or when the user switched windows. The window input went to is remembered with the host's series key (_wcuSeries), so input and observations without a window target keep to it after the foreground went back to the user. type_text preserves the current focus by default, so it can follow an OCR/visual click without refocusing another control. focusMode:main explicitly requests heuristic main-control focus.

The server classifies calls with isQuietCall (mcp/catalog.mjs), shared with the host's activity tracking: reads, list_windows, wait, background dispatch, browser-lane calls and element actions that start in the background take a quiet lease (no takeover helper, so no indicator and no global Esc), and only a call that uses the real pointer or keyboard turns on the series indicator. Element actions, scroll on an element and type_text in auto mode first run with _wcuQuiet; when they would need real input the backend throws WCU_NEEDS_INPUT before sending any, and the server runs them again with a normal lease.

RuntimeId references are cached from observations with HWND/PID ownership and a five-minute lifetime. Unseen/stale ids require re-observation; the backend does not globally search the desktop for them. Legacy tree paths remain view-dependent.

Actions report verification:sent. A UIA pattern call or native input acceptance does not prove the user's objective. wait_for supports native window presence, bounded UIA element queries, and literal OCR text. A satisfied observable condition reports verification:observed. Truncated UIA absence and occluded OCR remain inconclusive.

Input cancellation allows press/release cleanup before worker retirement. Timed-out input is never replayed. Clipboard formats are materialized before replacement. A private STA owns delayed text; restoration follows a confirmed target request and clipboard close, or completion of synchronous WM_PASTE in a native Edit/RichEdit. The native path still restores when a clipboard monitor rendered the text first, without waiting for a second render notification. Other controls use Ctrl+V; unknown readers leave the new text available and report clipboardRestored:false. Pasted text carries ExcludeClipboardContentFromMonitorProcessing, CanIncludeInClipboardHistory=0 and CanUploadToCloudClipboard=0, so it stays out of clipboard history and the cloud clipboard. Drag release is also attempted in finally.

## Browser lane

mcp/browser.mjs speaks the Chrome DevTools Protocol over an inherited pipe for temporary agent browsers and WebSocket for configured/kept shared browsers, beside the PowerShell backend rather than through it. It uses its own small WebSocket client without compression: Node's built-in client negotiates permessage-deflate and drops the connection on any message over 4 MiB decompressed, which the accessibility tree of a long page exceeds. A call routes there when it carries browserTab or a page element id. Each tab gets one flattened session; pages are read with Accessibility.getFullAXTree and flattened into an outline; input uses Input.dispatchMouseEvent / dispatchKeyEvent / insertText inside the page after a hit test. Element ids are numbers the server run hands out and maps to a DOM node of one document; tab ids carry a salt of the run, so ids from an earlier run never reach a tab. Actions in a tab run one at a time. Browser-lane calls take a quiet takeover lease: a stopped series still refuses them and settings reconnects wait for them, but they start no takeover helper, so they show no screen indicator and arm no global Esc; DSH's stop button cancels them. The agent browser is a visible-by-default child process (headless is opt-in) running the browser chosen in settings (by default the Windows default browser, read from UserChoiceLatest\ProgId, else UserChoice), whose tabs run in an isolated browser context of a throwaway profile; with sign-ins kept, it runs on a kept profile instead and its tabs use that profile's own context, so the sites the user signed in to there stay signed in. The experimental existing-browser option can connect a user's Chrome or Edge after DSH approval and browser consent; this exposes the connected browser's tabs, without per-tab enforcement. See safety.md. All usable presets receive browser-first routing instructions at MCP initialization; disabled tools are not advertised as callable. The visible agent browser marks its work without covering the page, as Codex's Browser Use does: a DSH-blue window frame (an autogenerated theme), a pointer badge as the icon of the tab DSH works in, and a small pointer at the point it acts on, drawn in a closed shadow root of an isolated world that lets pointer events through and is hidden for screenshots. Visible targets are created with background:true; automatic activation remains limited to headless tabs. A tab that is not painting (background or minimized) is captured by repeating the capture request until Chrome answers, never by activating its window.

## Vision

No visual model is bundled. A vision-capable caller or optional external parser such as OmniParser can consume screenshot content and return coordinates to the same guarded input tools.

## Approval and control state

`mcp/policy.mjs` classifies sensitive calls in the host and enforces policy in standalone MCP. Host grants are signed, exact-argument and single use across MCP worker restarts; consumed nonces remain in the adapter's control directory. An unavailable, corrupt or locked ledger fails closed. Reload the adapter to establish fresh control state after an interrupted ledger write. Each adapter holds a named pipe for its control directory lifetime; startup cleanup probes that pipe once, so a reused PID does not preserve a crashed adapter's directory. Directories from older versions retain their PID/age rules. `mcp/page-values.mjs` supplies the field-redaction function used by Chromium and BiDi. The keyboard hook has its own message thread and readiness event. Clipboard pastes use `scripts/windows-clipboard.cs` delayed rendering; without a confirmed read or native paste completion, the requested text is retained. Display and state-file failures are diagnostic and cannot replace a completed action with a failure.
